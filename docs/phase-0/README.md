# Phase 0 — Audit and production controls

**Authorised:** 23 August 2026
**Objective:** batch every repository asset, prevent simulated behaviour from presenting as production, establish engineering controls, and design Phase 1 without activating live payments.

## Current baseline

The generated registry covers **296 assets**:

- 134 application pages
- 95 API route files
- 59 Prisma models
- 8 repository datasets
- 4 scheduled API jobs (also counted among APIs)

Initial applet allocation is generated by `npm run registry:generate`. It is a discovery classification, not a declaration that an asset is production-ready.

## Controls implemented

- Five applets plus FORTIS CORE defined in the master plan.
- FORTIS ACADEMY / LEARN naming applied.
- Machine-readable module registry added.
- Known simulated financial, placeholder and false-live routes fail closed in production.
- Production readiness policy has automated tests.
- Node 20 and npm version policy pinned.
- Native `bcrypt` replaced by `bcryptjs` to remove fragile native installation and duplicate implementation.
- NextAuth upgraded to the patched 4.24.15 release.
- Secret-bearing tracked environment files removed; example environment sanitised.
- CI quality/security workflow template added; activation under `.github/workflows/` requires a GitHub credential with workflow permission.
- Phase 1 architecture, source, provider, AI and backlog artefacts added.

## Current gate status

No existing business module is automatically classified `production`. Assets start as `preview` or `internal` and must link evidence for the six production gates in the master plan.

## Known limitations requiring Phase 1

- Server-side authorization is not yet consistently applied to all protected APIs.
- The current Prisma schema is a broad legacy schema, not the approved Core domain schema.
- No licensed payment provider is connected.
- No provider-reconciled ledger exists.
- Most national datasets lack machine-readable provenance records.
- AI remains OpenAI-oriented in parts of the codebase; local/free adapters are not yet implemented.
- Many mock-bearing UI pages remain in source but are blocked from production where identified. They must be rebuilt or retired.
- The full lint/type/build baseline must be verified after Prisma engine/client generation succeeds in CI.
